# Evidence Status

Keep evidence labels strict. Do not merge current, historical, diagnostic,
synthetic, and model-only results into one claim.

## Evidence Labels

| Label | Meaning |
| --- | --- |
| CURRENT | Active evidence for the current thesis/runtime story. |
| HISTORICAL | Submitted-paper or old-run evidence; useful for lessons, not current claims. |
| REAL EXPERIMENT | Measured from actual Gazebo+YOLO runs or logged runs. |
| EVALUATION ONLY | Uses ground truth only to score outcomes or diagnose errors. |
| MODEL ONLY | First-principles or analytic prediction, not measured evidence. |
| SYNTHETIC | Generated by corrupting/sampling simulated geometry or CAD. |
| HYPOTHETICAL | What-if camera/layout that has not been physically run. |
| DIAGNOSTIC | Debugging or explanatory artifact; not a headline result. |

## Current Evidence Chain

A headline result needs the full chain:

```text
world
-> detector artifact
-> reliability/visibility data
-> GP artifact
-> config
-> logs
-> metrics
-> figures
-> matching paper wording
```

If any link is missing, the claim must be labelled exploratory or diagnostic.

## Geometry Visibility Evidence

The geometry visibility module must keep separate:

- real detector evidence,
- geometry model predictions,
- synthetic sensor emulations,
- hypothetical camera/layout changes.

Safe wording:

> The geometry/camera model provides a prior or what-if prediction. It becomes
> evidence only when checked against detector logs, held-out routes, or fresh
> captures.

## Active Caveat

If a simple range or distance baseline explains almost as much as a geometry
visibility model, say so. A realistic thesis is stronger when it reports that
the warehouse is low-occlusion and that range/obliquity may dominate.
