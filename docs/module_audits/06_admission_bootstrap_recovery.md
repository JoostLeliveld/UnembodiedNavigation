# 06 — Measurement admission, initialization and recovery

Reviewed 2026-09-06 against the working tree. **The corrected runtime preserves a supported blind turn and can recover on a later correction, but still refuses the first accurate return solely because the camera gap exceeds 1.5 s. Rejection inflation eventually admits an unchanged outlier. Upstream admission can prevent useful recovery evidence from reaching that filter at all.** These are distinct mechanisms and require distinct remedies.

No production code, configuration, calibration, frozen run or other audit was changed. This report separates implementation defects from deliberately retained policies. The request ended at “For policy”; the policy proposals below are reviewable experiments, not an inferred authorization to change the running baseline.

### Intentional policies that remain scientifically unresolved

**P01 — Total camera-gap refusal (P1, active).** Complete odometry for an east drive, 90° blind turn and north drive produces the exact correct predicted return pose (0.4,1.2,π/2). Its accurate camera at t=10 is still dropped; the next at 10.2 is accepted. The clock-freeze defect is repaired, but a stream with every usable correction >1.5 s apart can remain prediction-only indefinitely even with complete motion. Policy should depend on supported motion and processing delay, not camera absence. This is a useful-evidence rejection, not a false-acceptance safeguard that needs to apply when prediction is supported.

**P02 — Repeated inflation (P1, active).** Deterministic stationary prior Pxy=0.01 I, R=0.01 I, z=(2,0) every 0.2 s, Q=0, gate 9.21, reanchor/jump off: first NIS=200. After nine rejected events add 0.45 m², the tenth has NIS=4/0.47=8.5106 and is accepted. The posterior mean jumps to x≈1.957 m. This demonstrates inflation alone; it is not a camera-noise estimate. The same numbers can represent either an outlier with correct prior or correct camera with lost prior. No innovation-only policy can distinguish those two worlds. A separate sequence refuses four outliers then accepts z=(0,0), so positive recovery is also tested. Recovering lost state needs additional evidence, not unbounded automatic weakening of the gate.

**P03 — Point-prior camera admission (P1, active).** For actual warehouse camera A and a synthetic perfect hull box at (-8,0,0), the correct prior admits. An XY-shifted prior (-6,2,0) or 90° wrong heading refuses the same box as width_mismatch. P never enters that calculation. Under stationary wrong belief, repeat camera refusal produces no fused correction, so downstream inflation/recovery cannot activate; current belief publications keep the bad prior alive. This is a constructed geometric mechanism, not a claim that this pose was driven or that every camera is blocked in the pilot. A nonempty historical belief buffer with no matched pose also blocks startup-style quorum forever until matching belief publication resumes. Missing belief support and sensor invalidity need distinct reasons/modes.

**P04 — Ordering and disagreement (P2, optional direct; startup tie policy active).** With Pxy=0.05 I and simultaneous zA=+0.6,zB=-0.6, R=0.01 I, first update passes (NIS=6), second fails after prior contraction. A-first yields +0.5 m, swapping which physical reading owns the lexically first camera ID yields -0.5 m. Reversing list arrival order within the same batch changes nothing because sorting is deterministic; separate callback order can still choose the first evidence. Simultaneous consistent cameras both contribute and exact duplicate batch does not change P. Joint gating against a frozen common prior or explicit robust batch inference is a policy choice; arbitrary camera naming should not choose which equally plausible hypothesis survives.

Manager pair disagreement has another semantic boundary: two cameras 0.9 m apart each lie 0.45 m from median and both pass the “0.6 m” gate; at 1.3 m separation both fail. Therefore 0.6 m is a radius to median, not maximum pairwise disagreement. Bootstrap diameter 0.91 m is a different predicate; do not present these thresholds as interchangeable. Manager startup chooses among equal groups by camera ID, deterministically but without a statistical reason to prefer that hypothesis. Active manager quorum is distinct-camera safe because eligibility produces a dictionary keyed by camera; the direct quorum bug is not present there.

**P05 — Near-time/future-state admission (P2, active).** `_nearest_state_pose` can select a state at 10.1 for a capture at 10.0 rather than the available 9.8 state. This is information available at processing time, not future information beyond receipt, and is not GT. Nevertheless it is a different-time pose without interpolation and can include a posterior from a later camera event. No revision/capture provenance prevents such circular use; nearest endpoints for common-time propagation need not bracket the interval or include its motion. Retain a causal prediction-at-capture record; if using smoothing, declare its information set and avoid using the tested observation to certify itself.

There are **no filter rejection counters to reset** in the active fused path: every rejected statistical event inflates and every accepted event contracts through the update. Gate counters in manager are cumulative diagnostic reason counts, not independent evidence or recovery streaks. `_last_correction_stamp` changes on bootstrap/accept/reanchor, not prediction holds; `belief_stamp` changes on holds/outages too. Per-camera seen timestamps are delivery watermarks, currently claimed too early. Selection contender streak is a separate optional mechanism and correctly excludes repeated frame timestamps. These variables must not be combined into one “rejection count”.

## Terminal assimilation accounting

The new probe checks seven ordinary identified branches: accepted→accepted/accepted; bootstrap→accepted_bootstrap/bootstrap; stale→dropped/stale_age; old→dropped/not_newer_than_belief; gap→dropped/replay_gap_too_large; NIS→rejected/nis_too_large; optional reanchor→reanchored/diverged. Each emits exactly one row with the supplied ID and nonempty reason. Existing envelope tests check malformed schema/frame/SPD and duplicate-ID integrity stops.

The exact registered selection is `logs/studies/icra_commissioning_20260905/network_navigation_runtime_evidence/selection.json`, SHA-256 `66b928fbaf8f470332acff23922003822fcb58113d4bd085180ade5c54c0cfd0`. Its run manifest, fusion observations and assimilations were hash-checked, then read with `aligned.observations` and `aligned.assimilations`. Additional assertions enforce set equality, uniqueness, known status and reason for every refusal; `aligned.assimilations` alone only checks ID uniqueness and does not enforce all those rules.

These are ledger counts, not independent samples or localization metrics. Reasoned drops remain valid experiment evidence. The verification establishes accounting **for logged fused publications in those selections**, not exactly-once delivery under every crash/interleaving. Invalid envelopes and callback/publication exceptions can fatal before a terminal row; the publication and log paths are not durable atomic transactions. Manager/experiment logs are the observed publication reference, not an independent DDS publication trace. Duplicate physical publication can be obscured by set-based checking, and the compatibility bootstrap can make a correctly counted refusal semantically false. Thus the universal “every published fused correction exactly one truthful terminal assimilation” property is **not established** by the current implementation. Add a durable identified input/commit ledger, one terminal refusal for every validly identified received event even on handled failure, and reconciliation for delivery failure; keep malformed ingress identity failures distinct from statistical recovery.

## Proposed isolated policy experiments

First repair the transaction, validation, motion-support and ledger defects above with regression invariants. Keep active NN/offset/R, process model, detector events, mission and existing baseline configuration fixed. Do not tune camera R to force innovations through. Proposed policy variants are intentionally separate:

Do not make “never accepts” the success criterion.
