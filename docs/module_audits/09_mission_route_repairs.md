Malformed mission JSON is also rejected as a complete configuration. A valid parsed prefix never becomes a shorter executable mission. Coordinates must be finite numbers; JSON integers normalize to ROS-compatible floats. ROS creation stamps are canonical and fit the message range. Duplicate coordinates remain distinct tour members. These are correctness checks, not spacing or radius changes.

`operational_belief_timeout_s=0.5` is **new runtime behavior requiring a successor freeze**. Mission previously had no delivery expiry. Its initial value matches the separately declared actuator `command_timeout_s=0.5`; this does not make the two policies equivalent. It is not justified by camera `pixel_timeout_s`. The operational producer is configured at 10 Hz (0.1 s period); tests accept state age exactly 0.5 s and refuse 0.500000001 s, including without another callback. Tests with an old camera anchor and a fresh supported prediction remain positive. The timeout applies to prediction-target age only, and must be finite and positive in mission configuration. Owner 13 was assigned launch/effective-config/rationale/freeze wiring and has added the named value to the launch/campaign path. Scheduling and delivery margin still require isolated deployment acceptance; no new campaign was launched here.

The mission consumer's reliable transient-local QoS matches 01's actual operational-state publisher. The helper uses schema version 1 with explicit epoch/revision, frame, state/anchor times, mean, full covariance, initialization and support. `initialized` is read explicitly when present; a missing field currently falls back to `revision > 0`. Current producer payloads include the explicit flag, and the producer-to-mission test uses the actual `PredictionSnapshot.to_dict()` implementation. The generic receiver can bind a new producer epoch; mission adds the stricter lifecycle latch required by the whole-stack restart contract.

Startup delay and periodic scheduling retain their existing wall-clock policy. Goal creation and mission progress use ROS time. `status_stamp_ns` records the source ROS time of cancellation independently of immutable goal creation time; it is nullable only when no valid nonnegative clock is available. The parser accepts its absence in earlier envelopes. On a rewind before any active goal was issued, the message describes only a cancelled configured target and uses reason prefix `before_first_publication:`. It never claims that an active target was sent.

The final tour goal stays `active` for owner 10 to judge operational success. Tests inside, at and just outside the intermediate radius preserve that boundary; final-goal tests inside/outside it verify that mission does not assert success or exhaust the target. The initial covariance threshold remains a first-release policy, not a new progress gate. Neither ground truth nor contacts enter mission readiness, handoff or success logic.
