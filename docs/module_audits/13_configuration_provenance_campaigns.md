# 13 — Experiment configuration, provenance and campaign execution

2026-09-06. **The campaign path does not yet guarantee that a completed ledger entry identifies the attempt, configuration and executable artifacts that produced its evidence.** Isolated reproductions confirm stale-summary selection, incomplete-run reuse, inconsistent override handling, missing manifest fields, concurrent ledger loss and unsafe legacy cleanup scope. Several recent repairs work in their tested scope; they do not close the entire chain.

This is the requested investigation and smallest-repair report. No production source, campaign YAML, model, calibration, existing log, registered selection or frozen experiment snapshot was changed by this audit. No live campaign, simulator, ROS graph, process termination or global cleanup was performed. Process failures and cleanup ownership were tested with fake processes and a temporary `/proc` fixture. A real campaign CLI invocation used `--dry-run` and a temporary output root.

## C13-01 — Completion discovers an old summary instead of the launched attempt

**Location/reachability:** captured [run_visibility_campaign.py:1203–1211](13_source_snapshot/afc15e464fec/scripts/visibility_comparison/run_visibility_campaign.py#L1203), [first-command directory discovery:1213](13_source_snapshot/afc15e464fec/scripts/visibility_comparison/run_visibility_campaign.py#L1213), [post-process selection:1444](13_source_snapshot/afc15e464fec/scripts/visibility_comparison/run_visibility_campaign.py#L1444). Every cell execution uses these functions, including the active runtime pilot. The user-facing audit did not use this rule to choose evidence.

**Trigger/expected:** a cell already contains an old completed attempt; a new attempt exits before producing its own summary. The ledger should identify the new attempt and record its infrastructure failure.

**Observed/reproduction:** the fixture creates `experiment_20000101_000000` with a summary and `experiment_20990101_000000` without one. A fake launched process exits 17. `_find_latest_run_dir` skips the new directory and returns the old one. `fresh_incomplete_goal`, `fresh_invalid_goal`, `fresh_interrupted` and `fresh_empty_summary` all record the old path. No matching run manifest is required in this fixture; valid synthetic correction files satisfy the separate accounting check.

**Consequence:** a failed rerun acquires old metrics/outcome, and the previous attempt can be relabeled as current work. Before a new logger directory exists, the independent “latest experiment” watcher can also inspect old command rows and incorrectly satisfy the first-command condition. The recent latch optimization reduces repeated scanning after command detection but does not establish attempt identity.

**Smallest repair:** allocate one unique attempt/run ID before `Popen`, pass its explicit directory and token to the logger, and require matching ID/token in manifest, summary and ledger. Read only that path. Record the new attempt's missing-summary failure; keep the previous attempt as an immutable separate entry. Directory timestamps may help a display, not select evidence.

## C13-02 — Terminal completion and resume validation fail open

**Location/reachability:** captured [summary reader:1137](13_source_snapshot/afc15e464fec/scripts/visibility_comparison/run_visibility_campaign.py#L1137), [fresh classification:1456](13_source_snapshot/afc15e464fec/scripts/visibility_comparison/run_visibility_campaign.py#L1456), [resume validator:711](13_source_snapshot/afc15e464fec/scripts/visibility_comparison/run_visibility_campaign.py#L711), [skip decision:1321](13_source_snapshot/afc15e464fec/scripts/visibility_comparison/run_visibility_campaign.py#L1321). Active fresh and resumed campaigns.

**Trigger/expected:** partial summary, `completed:false`, `valid_run:false`, malformed shape, missing evidence or wrong cell identity. Require a typed, closed terminal record for the requested attempt and distinguish valid experiment failures from infrastructure/evidence failure.

**Observed/reproduction:** with synthetic correction evidence passing, fresh classification maps `completed:false` plus `goal_reached` to `goal_reached`; `valid_run:false` plus a goal reason also becomes `goal_reached`. An incomplete interrupted summary becomes a skippable `interrupted`; `{}` becomes `completed`. Exit code 17 is ignored. Only the particular combination of outer timeout plus incomplete summary is rejected by that branch. `_read_run_summary` accepts JSON `[]`, allowing later `.get` failures instead of a typed refusal.

`resume_no_summary_or_csv`, `resume_partial`, `resume_malformed`, `resume_invalid` and `resume_failed` all pass `_existing_entry_matches_config` when its selected manifest predicates are satisfied. It never reads those summary/evidence files. A manifest with another seed, world, task and planner also passes the isolated identity case. The checker derives expected task/condition settings from the ledger entry, not a supplied authoritative requested tuple. Any outcome except null/`infra_invalid` can reach the skip branch; there is no terminal-outcome allowlist.

**Consequence:** “completed” and “already done” do not imply usable evidence; different consumers can disagree about the same run. Audit [10 L10-01/L10-02](10_logging_and_event_accounting.md) confirms why ignoring summary validity matters: some malformed/duplicate deliveries survive only as an in-memory invalid flag and are absent from canonical CSV rows. Audit [11 A11-02/A11-05](11_alignment_replay_and_reporting.md) finds separate validation gaps downstream.

**Smallest repair:** share one typed terminal validator with 10/11: exact cell/attempt identity, required manifest/schema fields, strict boolean completion/validity, explicit terminal status/reason, closed required files and raw correction accounting. Keep exit status and infrastructure state distinct from scientific outcome. Reasoned filter refusals and valid stuck/timeout/collision outcomes remain eligible evidence; do not select only goal-reaching runs. A newer cache/JIT options gate does not replace these checks.

## C13-03 — Tokens scope cleanup, but domains and roots are not leased

**Location/reachability:** captured [global cleanup:291](13_source_snapshot/afc15e464fec/scripts/visibility_comparison/run_visibility_campaign.py#L291), [token matching:322](13_source_snapshot/afc15e464fec/scripts/visibility_comparison/run_visibility_campaign.py#L322), [domain allocation:932](13_source_snapshot/afc15e464fec/scripts/visibility_comparison/run_visibility_campaign.py#L932), [campaign startup:1311](13_source_snapshot/afc15e464fec/scripts/visibility_comparison/run_visibility_campaign.py#L1311), [run environment:1376](13_source_snapshot/afc15e464fec/scripts/visibility_comparison/run_visibility_campaign.py#L1376).

**Trigger/expected:** another campaign or simulator exists, or two same-config campaigns start concurrently. Cleanup must be restricted to the owned attempt; transport and output ownership must be exclusive.

**Observed/reproduction:** `_force_fresh` sends `pkill -f` to broad known ROS/Gazebo/node patterns. It runs before, between and after legacy-mode runs independently of `cleanup_sim_stragglers:false`. Four commissioning YAMLs omit `cleanup_mode` and consequently select `legacy_global`: `baseline_cpu.yaml`, `field_pilot_cpu.yaml`, `field_pilot_remaining_cpu.yaml`, `network_planner_pilot.yaml`. This is source/dry-command inspection; no global cleanup was executed.

The exact environment-marker test correctly distinguishes `ours`, `ours_other` and `theirs`; scoped cleanup is a positive repair. However two independent runtime-pilot tokens both receive ROS domain **211** for index zero. IGN/GZ partitions differ but ROS global topics can share a domain. There is no root/domain lease; caller `ROS_LOG_DIR` can also make log roots overlap.
