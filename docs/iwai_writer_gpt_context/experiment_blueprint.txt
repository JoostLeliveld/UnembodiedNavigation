Experiment blueprint for the IWAI paper
=======================================

Purpose:
Define the experiment campaign before final tuning, so the paper can avoid post-hoc storytelling.

Central question:
Does learned state-dependent external-camera observation covariance improve route choice, belief quality, or safety-valid goal reaching compared with a constant-observability EFE baseline?

Fixed scenario:
- World: `warehouse_occ_light.world.sdf`
- Task: `main_shadow_tradeoff`
- Start: `(-2.0, 1.0, 0.0)`
- Goal: `(2.0, -1.0)`
- Runtime detector: YOLO segmentation model `logs/perception_models/yolo_simseg_smoke/model.pt`
- Learned artifact: `logs/visibility_comparison/current_gp/yolo_score_raw_gp.npz`
- Same state estimator, safety geometry, stopping logic, optimizer limits, and seed set across conditions.

Main conditions:
1. Constant-observability EFE baseline
   - Same EFE planner.
   - Fixed detector-observation covariance \(R_0\).
   - No learned GP observability field.

2. Learned YOLO-score-GP EFE
   - Same EFE planner.
   - GP-derived \(R_{\mathrm{eff}}\).
   - No direct visibility reward, cost, or route penalty.

Optional conditions:
3. Oracle/reference observability field
   - Use only as diagnostic or upper-bound.
   - Do not describe as a runtime perception method.

4. MPC diagnostic
   - Include only if objective is clearly documented.
   - If not a full classical MPC, call it diagnostic.

Not a main condition unless deliberately reintroduced:
- Runtime multistart route-family seeding. This was removed from paper code.
- Rollout families can still be used offline to explain route-choice tradeoffs.

Seeds:
- Minimum: 0, 1, 2.
- Prefer 5+ if runtime permits.
- Report every run, including invalid, interrupted, stuck, and timeout runs.

Primary task and safety metrics:
- valid_run
- collision_any
- wall/obstacle penetration
- minimum goal distance
- final goal distance
- completion reason
- path length
- elapsed time after first command
- valid completion rate

State-estimation metrics:
- mean/max truth-state error
- mean/max truth-belief error
- yaw error for odom/state/belief
- belief covariance trace or position covariance ellipses
- pixel correction age and stale-correction fraction

Planner/runtime metrics:
- mean/median/p90 solve time
- optimizer success/status
- EFE total, risk, ambiguity, obstacle, control
- risk split: risk_mean, risk_cov_trace, risk_cov_logdet
- p_vis_plan and p_vis_plan_eff
- r_plan_u_std and r_plan_v_std
- fraction of horizon in low predicted reliability
- fraction of horizon in high ambiguity
- terminal predicted goal distance/progress as diagnostics

Recommended main paper plots:
- Problem setup figure: Gazebo screenshot + top-down constant-\(R_0\) snapshots from real trace.
- GP mean/conservative/uncertainty map.
- Path overlay for constant-\(R_0\) and learned GP EFE.
- Goal distance over time.
- State error and covariance over time.
- EFE risk/ambiguity/obstacle/control over time.
- Solve-time distribution or time series.

Appendix or supplementary plots:
- YOLO score histograms and calibration caveat.
- Heading variability in GP captures.
- Pixel correction age.
- Rollout family probes at route-choice times.
- Full run table with invalid/stuck/interrupted reasons.

Validity rules:
- Any collision or wall/obstacle penetration invalidates success claims.
- Interrupted runs are not completed successes.
- `stuck` near the goal is reported separately until stopping logic is improved.
- Near-goal stuck runs can be qualitative case studies, not clean aggregate successes.

Decision criteria:
- Learned GP EFE is better only if it improves valid completion, min/final goal distance, or belief quality without increasing collision/penetration.
- If constant and learned conditions choose similar routes, inspect whether the GP creates enough contrast in \(R_{\mathrm{eff}}\).
- If learned observability only helps after adding a direct visibility penalty, report that as engineering, not the main active-inference claim.
- If actuation noise is added, use the same noisy command wrapper for all conditions.
