Proposed IWAI paper outline
===========================

Working title:
Visibility-Aware Expected Free Energy Navigation with Learned External-Camera Observability

Abstract target:
State the external-camera navigation problem, the EFE mechanism, the learned GP observability model, the constant-observability comparison, and the preliminary result/caveat in about 150-200 words.

1. Introduction
- Concrete warehouse example: shortest path can pass behind a shelf and degrade external-camera localization.
- Explain why collision-free path planning is not enough when localization depends on future observations.
- Introduce EFE as a framework where preferred outcomes and expected observation ambiguity shape action.
- State the paper question:
  Does a learned state-dependent external-camera reliability model change EFE navigation behavior compared with a constant-observability baseline?
- Contributions:
  1. Formulation of external-camera navigation with state-dependent observation covariance inside EFE.
  2. YOLO-score-derived GP observability field with uncertainty-aware conservative planner map.
  3. Logged benchmark pipeline and diagnostics for route choice, EFE terms, safety, and estimation quality.
  4. Predefined experiment plan for comparing learned observability against constant-observability baselines.

2. Related Work
- Active inference and EFE planning.
- Perception-aware and visibility-aware robot navigation.
- External-camera localization and detector-based state estimation.
- Gaussian-process modeling of spatial reliability/observability.
- Keep this concise; use existing `references.bib` and do not invent citations.

3. Problem Formulation
- Planar robot state, unicycle dynamics, fixed external camera, known workspace and obstacles.
- Belief over robot state.
- Camera observation model in image space or homography-derived BEV path.
- Goal as preferred observation/state.
- Define the comparison variable: constant versus learned state-dependent observation reliability.

4. Expected Free Energy Planner
- Predictive belief rollout.
- Predictive observation moments.
- Risk as KL to preferred observation distribution.
- Ambiguity as conditional observation entropy.
- Auxiliary feasibility terms: obstacle/workspace barriers.
- Receding-horizon optimization and local-solver limitations.

5. Learned Observability Model
- YOLO segmentation detector and raw score.
- Offline capture, heading repetition, heading-marginal target.
- Logit-space GP regression with RBF kernel.
- Conservative planner map.
- Belief-aware visibility query.
- Precision-space blend from visibility/trust to `R_eff`.
- Caveats: uncalibrated confidence, 2D heading marginalization, simulator-generated labels.

6. Experimental Protocol
- Fixed world/task/start/goal.
- Methods to compare:
  - Constant-observability baseline.
  - Learned YOLO-score GP EFE.
  - Optional oracle/reference observability field only if clearly labeled.
  - Optional MPC diagnostic only if objective is clearly described.
- Seeds: at least 0, 1, 2; more if runtime permits.
- Same detector, GP artifact, state estimator, safety logger, stopping logic.
- Primary metrics:
  final/min goal distance, valid-run rate, collision/penetration, path length, time after first command, solve time.
- EFE diagnostics:
  risk, ambiguity, obstacle, control, `p_vis`, `R_eff`, fraction low visibility/high ambiguity.
- Safety validity:
  collisions and wall/obstacle penetration invalidate success claims.

7. Preliminary Case Study / Results
- Present completed case-study run `experiment_20260422_180449`.
- Present recent supporting completed run `experiment_20260423_111758` carefully.
- Show route, goal distance, validity, EFE decomposition, visibility/trust, state error, solve time.
- Say clearly that `completion_reason=stuck` near the goal is a termination-label issue to investigate, not a clean success label.
- Do not claim final statistical validation until full experiment batch is run.

8. Discussion and Limitations
- Learned observability can influence planning without direct visibility cost.
- Risk tuning and goal prior schedule are important.
- Runtime solve time and callback timing can affect pixel correction age.
- YOLO raw score is not calibrated probability.
- 2D GP averages heading effects.
- Engineering guards should be separated from active-inference claims.
- Runtime route-family multistart seeding has been removed from paper code; use rollout-family probes only as offline diagnostics unless reintroduced deliberately.
- Next experiments should be predefined and run under fixed comparison hygiene.

9. Conclusion
- Reiterate method and evidence.
- State the next validation step: controlled multi-seed comparison with fixed baselines and safety accounting.
