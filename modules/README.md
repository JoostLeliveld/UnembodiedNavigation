# Modules — the contribution front door

[Back to repository overview](../README.md)

One folder per **functional contribution** in the external-camera reliability
stack, ordered along the pipeline chain. Each module is a landing page: the
claim it makes, what you can see, which runtime code implements it, which
`research_story/` chapter it serves, and — where they exist — the external
baselines it is compared against and the paper framings built on it.

Modules **do not own runtime code or data**. Runtime code stays in
[`../src/`](../src/); investigation code + data stay in
[`../experiments/`](../experiments/) and `../logs/studies/`; locked media stays
in [`../paper_artifacts/`](../paper_artifacts/). A module *points at* those and
renders its demo from cached data (no Gazebo at render time).

## Per-module layout (the target shape)

```
NN_name/
  README.md      claim · status · owning chapter · what you'll see · code pointers
  demos/         rendered figures (+ run.sh / render_*.py once a demo is built)
  baselines/     external papers reimplemented as comparisons FOR this contribution
  framings/      candidate framings of our own paper centered on this contribution
```

`demos/` is populated for 01/02/04/08 (static figures regenerated by
[`../scripts/paper_figures/make_readme_visuals.py`](../scripts/paper_figures/make_readme_visuals.py)).
`baselines/` and `framings/` are created where they have content (07 holds the
Toro-Diz baseline notes and the multi-camera fusion paper framing); a module
without them has none yet. **Demo grammar** (four panels + one animation) and
the per-contribution demo standard are defined in
[`../research_story/DEMO_LAYER_PLAN_2026-07-16.md`](../research_story/DEMO_LAYER_PLAN_2026-07-16.md).
